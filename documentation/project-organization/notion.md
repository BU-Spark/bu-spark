## Project Notion Board

Each project team is provided with a dedicated Notion workspace that serves as the central hub for project organization and communication. This workspace contains important project resources, including links to the project GitHub repository, project description, documentation, meeting notes, and a shared task tracking board.

Students are responsible for keeping their team's Notion board accurate and up to date throughout the duration of the project. Maintaining the board ensures that Product Managers (PMs), Technical Product Managers (TPMs), and other team members have a clear understanding of project progress and current priorities.

## Task Management Expectations

All development work should be tracked using the team's Notion task board. Each task should include the appropriate metadata so that it can be effectively prioritized, planned, and reviewed. At a minimum, students are expected to keep the following information current where applicable:

- **Priority** – Indicates the relative importance of the task.
- **Sprint** – Identifies the sprint in which the task is planned or being completed.
- Any additional project-specific fields requested by the PM or TPM.

In addition, task status should be updated as work progresses. Tasks should be moved through the appropriate workflow stages, such as:

- **Backlog**
- **Ready**
- **In Progress**
- **Ready for Review**
- **Blocked**
- **Done**

Updating task status should be part of each developer's normal workflow rather than something completed only at the end of a sprint.

## Why This Matters

The Notion board serves as the team's single source of truth for project planning and progress. Keeping it up to date enables Spark! team members and students to maintain project history, monitor progress, identify blockers, coordinate code reviews, and plan effectively.
